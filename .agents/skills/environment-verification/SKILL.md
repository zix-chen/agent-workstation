# Verify an environment

Resolve the target service and environment from current configuration rather than guessing names or endpoints.
Read applicable rules and deployment/integration instructions. Prefer existing authenticated CLI/API routes.
Start read-only. Compare the deployed revision, relevant non-secret settings, health and a scoped business response.
A healthy process is not a business success; an API response is not proof of UI rendering.
Changes to flags, data or deployments require the user's scope, a restoration plan and read-back verification.
Report the source, observation time and evidence level. Never include credentials or full sensitive config dumps.
